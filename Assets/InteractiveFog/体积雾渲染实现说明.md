# 交互体积雾渲染实现说明

本文说明 `Assets/PolygonTown/Scenes/Demo.unity` 中交互体积雾从欧拉流体场到屏幕像素的完整渲染链路。

## 核心结论

本项目的雾不是粒子系统。Compute Shader 负责生成离散的密度场和速度场，Ray Marching Shader 负责沿摄像机视线生成临时采样点，并将这些采样点的雾密度、颜色和透射率积分成一个屏幕像素。

```text
交互物体移动
    ↓
向欧拉网格注入密度和速度
    ↓
平流、涡度、散度、Jacobi 压力迭代、压力梯度消除
    ↓
得到 Density Texture 和 Velocity Texture
    ↓
对雾体覆盖的屏幕像素执行 Ray Marching
    ↓
沿视线采样流体纹理、FBM 噪声和高度衰减
    ↓
Beer-Lambert 透射积分
    ↓
雾散射颜色与场景颜色合成
```

欧拉流体求解负责决定雾场怎样随时间变化；Ray Marching 负责决定摄像机当前能看到什么。

## 一、流体阶段输出什么

K3D 将模拟区域划分成三维体素网格，每个格子主要保存：

\[
D(x,y,z)=\text{密度或交互强度}
\]

\[
\mathbf{u}(x,y,z)=\text{速度向量}
\]

K2D 则只保存 XZ 平面：

\[
D(x,z),\quad \mathbf{u}(x,z)
\]

这些网格不是可见的小方块，也不是雾粒子，而是 RenderTexture 中的数值。GPU 在两个或八个相邻网格之间进行双线性或三线性插值，使 Ray Marching 能在任意位置取得连续近似值。

压力、散度和涡度纹理是求解过程的中间数据。Ray Marching 不直接读取它们：压力投影先修正速度，速度再运输密度，最终渲染主要读取修正后的 Density Texture 和 Velocity Texture。

## 二、逐像素产生摄像机射线

雾区域由一个 Box 或 Frustum Proxy Mesh 限定。这个 Mesh 只负责告诉 GPU 哪些屏幕像素可能看见雾，并不代表雾由实体网格组成。

对于被雾体覆盖的每个渲染目标像素，Fragment Shader 构造：

```hlsl
rayOriginWorld = _WorldSpaceCameraPos;
rayDirectionWorld = normalize(input.positionWS - rayOriginWorld);
```

High 通常在完整相机分辨率上执行；Medium/Low 在缩小的雾 Render Target 上执行，因此这里的“每个像素”指当前雾渲染目标中的像素。

## 三、计算射线在雾中的有效区间

Shader 将射线变换到雾体局部空间，与单位 Box 求交，得到：

- `nearDistance`：射线进入雾体的位置；
- `farDistance`：射线离开雾体的位置。

随后读取当前屏幕像素的场景深度，将终点截断到最近的不透明物体：

```hlsl
farDistance = min(farDistance, SceneDistance(screenUv, rayOriginWorld));
```

因此摄像机到人物或建筑物表面之间的雾仍会被积分，但 Shader 不会继续计算物体背后的雾。这就是场景深度遮挡。

```text
摄像机 —— 雾采样 —— 雾采样 —— 人物表面 | 人物背后不再步进
```

## 四、沿射线生成临时采样点

有效射线长度为：

\[
L=farDistance-nearDistance
\]

Shader 根据射线长度和画质配置确定采样步数：

\[
\Delta s=\frac{L}{steps}
\]

然后从近到远循环：

```hlsl
samplePosition = rayOrigin + rayDirection * distanceAlongRay;
```

这些 `samplePosition` 只是当前像素着色时临时计算的三维坐标，不会生成 GameObject、Mesh 或粒子，也不会跨帧保存。

自适应步进会让较短的穿雾路径使用较少采样，较长路径使用较多采样；射线起点加入小幅 Jitter，减轻固定步长产生的层状条纹。

## 五、采样 K2D/K3D 流体纹理

每个世界空间采样点先映射到模拟纹理的 `[0,1]` 坐标：

\[
UVW=\frac{worldPosition-simulationCenter}{simulationRange}+0.5
\]

K3D 使用完整 XYZ 坐标：

```hlsl
density = SAMPLE_TEXTURE3D_LOD(_Density3D, sampler_Density3D, uvw, 0).r;
velocity = SAMPLE_TEXTURE3D_LOD(_Velocity3D, sampler_Velocity3D, uvw, 0).xyz;
```

所以相同 XZ、不同 Y 高度可以得到不同的密度和速度。

K2D 只使用 XZ：

```hlsl
density = SAMPLE_TEXTURE2D_LOD(_Density2D, sampler_Density2D, uvw.xz, 0).r;
float2 velocityXZ = SAMPLE_TEXTURE2D_LOD(_Velocity2D, sampler_Velocity2D, uvw.xz, 0).xy;
```

K2D 中相同 XZ、不同 Y 的采样点读取同一份流体数据，垂直形状再由高度衰减和三维噪声塑造；K3D 的高度变化直接存在 Texture3D 中。

PolygonTown Demo 当前启用的“3D交互展示”使用 K3D，所以主效果直接读取三维 Density/Velocity Texture。

## 六、把流体数据转换为可见雾密度

Demo 是“整个区域先充满雾，交互物体经过后清出通道”的模式。此时流体 Density Texture 更接近交互强度场，而不是最终绝对雾密度。

Ray March Shader 先将模拟密度经过响应、反转阈值、边缘羽化等处理，再与基础雾相乘。其核心关系可以简化为：

\[
densityMultiplier\approx InitialDensity+SimulationDensity\times DensityScale
\]

Demo 使用 `Initial Density = 1` 和负的 `Density Scale`。因此：

- 没有交互时，模拟密度接近 0，基础雾保持完整；
- 交互物体向网格写入正密度后，负的 `Density Scale` 降低最终雾密度，形成清雾通道。

可选的 Direct Clear 还会根据交互物体世界坐标直接计算一个球形清雾 Mask。它不依赖流体传播；验证欧拉流体效果时应关闭 Direct Clear。

## 七、FBM 噪声、速度和高度衰减

每个采样点的最终可见密度大致为：

\[
\rho=BaseDensity\times InteractionMultiplier\times ShapedNoise\times HeightFalloff
\]

- `BaseDensity`：控制整体浓度；
- `InteractionMultiplier`：密度场形成的清雾/增雾影响；
- `ShapedNoise`：程序化 FBM 或烘焙 3D Noise，提供不规则体积细节；
- `HeightFalloff`：让雾随高度衰减；
- `Velocity`：在 Compute Shader 中运输密度，同时在 Ray March Shader 中偏移噪声坐标，使细节沿局部流向产生扭曲。

对应核心代码：

```hlsl
float3 noisePosition = noiseRayOrigin + noiseRayDirection * distanceAlongRay
    - simulationVelocity * (_VelocityScale * 0.025);
float noise = FogNoise(noisePosition);
float sampleDensity = _BaseDensity * densityMultiplier * shapedNoise * heightDensity;
```

FBM 噪声负责雾的视觉细节，不负责流体运动。真正跨帧传播的交互形状来自欧拉密度场和速度场。

## 八、Beer-Lambert 透射积分

每个采样点得到密度后，Shader 根据 Beer-Lambert 定律计算这一小段介质产生的不透明度：

\[
\alpha=1-e^{-\rho\Delta s\,k}
\]

其中 `ρ` 是采样密度，`Δs` 是步长，`k` 是项目中的消光缩放系数。密度越高或光在雾中走得越远，该段的不透明度越高。

项目使用从近到远的前向累积：

\[
C_{fog}\mathrel{+}=T\alpha C_{sample}
\]

\[
T\mathrel{*}=1-\alpha
\]

- `Csample`：当前点经过密度颜色、近似光照和吸光处理后的颜色；
- `T`：穿过此前所有采样点后剩余的透射率；
- `Cfog`：当前像素累计的雾散射颜色。

当 `T < 0.01` 时，后面的贡献已经几乎不可见，循环提前终止。这是浓雾提前终止优化。

## 九、与场景颜色合成

Ray Marching 输出预乘的雾散射颜色和剩余透射率，最终关系为：

\[
C_{final}=C_{fog}+T\times C_{scene}
\]

High 使用传统全分辨率透明体积 Pass，直接按照上述关系混合。Medium/Low 先把未合成的 `scattering + transmittance` 和代表性雾深度写入低分辨率 Render Target，再使用全分辨率场景深度进行双边重建，最后合成进 Camera Color。

双边重建会降低跨越人物、建筑轮廓采到错误雾值的概率；低分辨率路径的主要收益是减少执行 Ray Marching 的像素数量。

## 十、速度、密度和压力对渲染的影响关系

| 数据 | Ray March 是否直接采样 | 对画面的作用 |
|---|---:|---|
| Density | 是 | 决定交互区域最终增雾或清雾的强度 |
| Velocity | 是 | 主要在模拟阶段运输 Density；渲染阶段还用于偏移噪声坐标 |
| Pressure | 否 | 修正 Velocity 中不合理的汇聚和发散，间接改变 Density 的后续运动 |
| Divergence | 否 | 为压力求解提供速度流入/流出不平衡信息 |
| Curl/Vorticity | 否 | 修改 Velocity 的旋转细节，间接影响 Density 形状 |

完整因果链是：

```text
Pressure / Divergence / Vorticity
              ↓
          修正 Velocity
              ↓
       Velocity 平流 Density
              ↓
 Ray March 采样 Density + Velocity
              ↓
          屏幕中的雾
```

## 十一、推荐的调试验证

在 `Tools > Interactive Fog > Show Debug Window` 中：

1. 关闭 `Ray March 直接清雾`，排除直接球形 Mask；
2. 开启 `Ray March 采样流体场`；
3. 开启交互密度注入和交互速度注入；
4. 观察 Density 和 Velocity 预览；
5. 分别关闭密度平流、速度平流和压力投影，比较通道传播与稳定性；
6. 每组 A/B 对比前清空场，避免上一组残留状态干扰。

关闭 Ray March 流体采样后，Compute Shader 仍可继续更新纹理，但画面只显示基础雾和可能开启的 Direct Clear。这可以证明“模拟”和“渲染”是解耦的。

## 十二、面试回答版本

> 项目的雾不是粒子，而是欧拉网格与 Ray Marching 的组合。Compute Shader 在二维或三维网格中保存密度场和速度场，通过平流、涡度、散度计算、Jacobi 压力迭代和压力梯度消除更新流体。渲染时，摄像机针对每个雾渲染像素构造一条射线，计算射线进入和离开雾体的位置，并使用场景深度把终点截断到最近的不透明物体。Shader 随后沿射线生成多个临时采样点，在每个点采样 K2D 或 K3D 的 Density/Velocity Texture，再结合 FBM 噪声、高度衰减和基础密度得到最终采样密度。每一段通过 Beer-Lambert 定律转换为透明度，从近到远累积散射颜色和透射率，最后使用 `雾散射颜色 + 场景颜色 × 剩余透射率` 完成合成。Ray March 采样点只是着色过程中的坐标，不是实际粒子。
